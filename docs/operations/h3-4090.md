# 4090 ComfyUI 接线与执行

使用指定 RTX 4090 的 ComfyUI。原工作流目录相对于 ComfyUI 根为 `user/default/workflows/社区精选H3_人物与场景替换_实验`。源工作流以实际 JSON、哈希和活动分支定位。实际设备路径与配置见项目私有说明。[配置示例](<../../configs/project.example.toml>) · [工作区](<../maintenance/workspace.md>)

## 工作流选择与副本

| 项目 | 做法 |
| --- | --- |
| 原图与副本 | 优先复用现有工作流。允许复制所需原图、依赖的工作流和 API 图。新增接线、输入位或参数调整放在项目工作副本或本次 API 图，原图优先保持只读。输入清单记录原工作流与实际执行版本、路径及哈希。 |
| 整片输入 | 活动视频输入位接指定原片全片。由工作流完成视频动作解析与迁移。按实际能力核对格式、时长、帧数、帧率和画幅，工作流所需的重采样覆盖完整视频。缺少完整输入能力时记录阻塞。 |
| 目标版本 | 两版传入同一完整原片。单人换用各自的定稿图。双人两版使用相同的 SA02 与 BM01，按已记录的交叉绑定匹配实际输入位。 |
| 运镜 | 推拉、摇移、变焦等以原片为目标。轮廓路线保留人物相对画面的位移、尺度等变化，不独立求解相机位姿；人物与场景各有参考图。 |
| 动作道具 | 需要扇子、球等道具才能完成动作时，选用支持该道具的目标图和工作流。按版本记录缺少的配置。 |
| 画幅与编码 | 默认沿已接通路线的输出规格。明确要求 9:16 等规格时选对应配置，匹配所需构图。 |
| 音轨 | 优先沿整片时间轴保留适用源音。无法保留时使用静音并注明。生成音仅在明确指定时使用。 |

路线以实际输入映射、可执行分支及取回结果登记。样片用于确认流程能提交完整输入并取回两个版本。一个工作流可覆盖多个实际接通的组合。[流程验证](<../verification/acceptance.md>)

<a name="s02-contour-redraw"></a>

## 站立单人：S02 轮廓引导纯重画

用户验收通过的竖屏 SA02 全身样片采用下列接线。只在 API 副本中适配；不改 4090 原工作流。站立单人的其余构图沿用同一方案，内容验收按成片独立判断。

| 条件 | 定稿做法 |
| --- | --- |
| 全片动作输入 | 从 0 开始、帧数不限、按 24 fps 解码。轮廓处理尺寸 9:16 用 432×768，16:9 用 768×432。BiRefNet 以两帧为推理批生成前景轮廓，转灰度图后用 Canny 0.25／0.55 提取边缘，再按顺序合回完整时间轴。推理分批不是对视频分段。 |
| 生成参考 | `<Picture 1>` 对应 `ref_image_0`，使用 F01／F02 或 F05／F06 正式目标图；`<Picture 2>` 对应 `ref_image_1`，使用 S02 空场母版。两张图短边预处理为 928，`ref_image_size=max`。原片 RGB 不接 H3 视频参考，也不接控制节点的 `source_video` 或重绘蒙版。 |
| 采样 | H3 Fun ControlNet Union 2.0 只在一采接完整轮廓序列：强度 0.85，采样范围 0–1。保留一采 → 潜空间放大 → 二采，二采不接轮廓控制。每个尝试钉住所用模型、LoRA、采样参数及种子。 |
| 输出 | 原片音频接独立音频参考和最终音轨。图像由 H3 整段重画，裁去模型对齐的尾部填充，以 24 fps 编码 MP4。不做图层、贴图或背景合成。 |

Prompt 保留六段：`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。第一张图定义身份、服装、成像媒介和构图；第二张图定义唯一环境。把连续动作、时序和镜头相对轨迹绑定到轮廓，不引用原片场景。完整镜头只重画同一个无缝白场，浅灰透视网格只在地面；新露出的区域仍是白场。半身不强制补出脚步。原音沿整片时间轴保留。

轮廓和双图是生成条件，不是相机轨迹或背景像素锁。可复现的完整 Prompt、输入清单、实际执行图和回执留在项目私有批次记录；不能将单条成片验收外推到所有角色、画幅和镜头。

<a name="submission"></a>

## 提交与找回

1. 入队前为每条原片准备 SA02 和 BM01 两版计划，核对同一批次和完整原片的 SHA256。各版分别保存尝试标识和实际输入清单，记录人物绑定、目标图、场景、活动分支和实际参数。记录工作流支持的实际种子。由工作流完整迁移原片动作。
2. 两版都就绪时同轮提交。已取回的匹配版本引用原产物，缺少接线的版本登记阻塞。各版首次提交一次，按各自回执查询队列、历史和输出。断线、超时或回执不明时，保留 `unknown` 并核对原尝试。
3. 批次仍在执行时，查实未提交可按原计划提交。确认失败且找到可修正原因时，每次常规请求的每个版本最多自动补跑一次。故障补跑优先沿用原种子，只调整引起失败的参数。用户说「重做这版」时另建尝试，沿用人物绑定和目标图。工作流支持时默认换种子。用户另有指定时按指定配置。
4. 每次生成有结果便反馈。运行中的批次按版本和回执取回实际 MP4 后直接交付，确认失败则附该次失败原因和补跑安排。已生成但暂未取回时，反馈生成结果与取回状态。[运行记录](<run-record.md>) · [交付条件](<../verification/acceptance.md#delivery-review>)

<a name="queue-and-stop"></a>

## 排队与停止

每条会话消息的链接默认归入一个新批次，以批次编号登记。客户明确要求追加时并入指定批次。每批原片按输入顺序两条一组。组内另一条原片仍在下载时等待。两条都就绪后依次提交源 1 SA02、源 2 SA02、源 1 BM01、源 2 BM01，再处理下一组。另一条已明确失败或阻塞时，就绪原片按单条提交，末组只有一条时也直接提交。缺图或前置失败的版本按实际状态反馈。就绪任务进入指定 ComfyUI 队列，4090 正在运行时也可入队。

收到停止指令时，停止当前批次的全部未完成任务，覆盖两个版本及尚未提交、排队和正在运行的尝试。暂停本批次的提交与自动补跑。按回执移除队列中属于本批次的任务。正在运行的任务使用能限定到该批次任务的中止能力。确认停止后记为 `cancelled`，尚未提交的尝试也登记停止结果。设备不支持按归属中止或停止结果暂未确认时，保留原回执并反馈实际状态。结果不明的尝试记为 `unknown`。如果某版已经生成成功，MP4 还在 4090 上，先反馈生成结果并保留原回执，待该批次恢复后再取回。

<a name="batch-resume"></a>

## 恢复批次与补发结果

- 用户说「继续这批」时，默认恢复所指批次内所有剩余任务。明确点名原片或版本时按指定范围恢复。按原回执取回已生成的结果，已确认取消的任务另开尝试，待提交的在条件具备时入队。已交付版本沿用原成片。原回执状态未明的尝试继续核对，排队中或运行中的沿用原回执。
- 会话意外中断后，恢复会话时依据本地批次记录核对原回执，逐条补发尚未反馈的结果。正在运行的尝试沿原回执跟进。已明确停止的批次仍按停止后的取回规则处理，用户发出继续指令后恢复。[反馈记录](<run-record.md>)
