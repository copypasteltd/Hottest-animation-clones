# 动作迁移执行手册

此手册描述 v0.4 的执行顺序。路线的启用状态以样片证据和项目配置为准。[产品需求](<../product/requirements.md>) · [当前进度](<../product/status.md>)

| 顺序 | 接收 | 交给下一步 |
| --- | --- | --- |
| 1. 下载 | 用户提供的作品链接 | 已核验原片及来源侧车 |
| 2. 判断 | 原片及回看证据 | 执行区间、可见范围、目标取景、姿态和表演人数 |
| 3. 选图 | 判断结果及项目角色预设 | 带版本的目标图及表演者映射 |
| 4. 执行 | 源视频、目标图和匹配的 H3 工作流 | 原任务回执和已取回的候选视频 |
| 5. 交付 | 候选视频、源动作证据与回执 | 通过审核的成片及结果说明 |

## 下载与验片

1. 核实作品身份。Bilibili 保留 BV／av 及链接选择的分 P，X 以具体帖子及其中的视频为准，抖音以可核实的作品页为准。短链沿下载技能支持的方式解析。多视频链接缺乏明确选择时登记待复核，重复输入保留逐条结果并引用同一来源记录。
2. 用 `/ra-video-download` 处理指定作品。使用本项目内的私有素材目录 `media/sources/<source_id>/`，保存原片和来源侧车。Windows 工具链、平台限制、认证和下载回退按技能实际规则处理。复用或新增文件时保留现有原片。
3. 按技能交接结果检查非空文件、视频流、实际音轨和有效时长。记录下载方式、大小、SHA256、画幅、帧率和音视频编解码信息。遇到缺少音轨、媒体探测失败或其他交接失败时，按下载技能的实际结果登记原因。来源链接与原始元数据随私有素材存放。处理范围以用户给出的作品及本次任务为准，素材涉及的传播和再使用条件随成片记录。

<a name="routing"></a>

## 判断取景、人数和姿态

默认覆盖完整连续表演。记录源视频毫秒时间区间 `[start, end)` 和关键动作时刻，回看开头、核心动作和结尾。遇到快速手势、遮挡或主体变化时加密检查。超出工作流能力或需要分段时，逐段登记起止、原因与未处理范围。

| 判断 | 可复查的依据 |
| --- | --- |
| 半身 `half_body` | 关键动作落在头肩、躯干、手臂或双手，且所需部位在关键时刻可辨认。源片只拍到腰部时，也可采用膝部中景目标图。腿部补全按实际证据标限制。 |
| 全身 `full_body` | 脚步、接地、起蹲、转身或位移是关键动作。观察所需的头、手、腿、足与地面关系。关键部位缺证时记录待复核范围。 |
| 单人 `single` | 一名主体完成目标表演。偶然入镜的路人可记为旁观者。 |
| 多人 `multiple` | 多人参与共同动作、互动或队形。记录实际人数、相对站位和持续对应。换镜、换人和人数变化按区间判断。 |
| 姿态 | 以实际表演和目标预设为依据。目前有站立 S02，坐姿等配置可各自使用半身或全身。 |

保存源可见部位、关键时间点、目标取景、动作范围和选择理由。证据不足使用 `needs_review`。例如，单人手势片可选择半身。两名表演者互换站位且脚步决定动作时选择多人全身。多人对应缺失或关键身体部位持续出框时，将受影响区间标为待复核。

<a name="target-selection"></a>

## 选择目标替换图

按姿态、取景、表演人数及已配置的角色匹配当前图。核对本地角色锁、组合清单、文件哈希和该图实际审核状态。多人及不同姿态的图各自按适用范围核对。多人执行时为每位表演者指定目标角色，并按已验证的节点输入绑定组合图或逐人图。缺少预设、正式图或对应关系时记录具体阻塞项。[S02 选图矩阵与文件核验](<../assets/reference-images.md#target-frames>)

## 启动工作流与交付

按接线指南锁定运行图和输入清单，以原提交回执跟踪至结果取回。通过媒体检查的候选进入视觉与动作审核，审核通过后交付到 `outputs/<run_id>/<item_id>.mp4`。交付摘要使用源 ID，列出成片路径、媒体参数、处理区间、音轨处理、审核结论及适用范围。批次中待审、阻塞和失败项各有原因和核对入口。[4090 执行](<h3-4090.md>) · [成片判定](<../verification/acceptance.md#delivery-review>) · [任务模板](<../templates/动作迁移任务与交付模板.md>)
