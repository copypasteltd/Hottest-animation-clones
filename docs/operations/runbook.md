# 动作迁移执行手册

常规输入是作品链接。获得完整参考视频后，为 SA02 和 BM01 各跑一次匹配的 H3 工作流。各版本按回执取回并直接交付。[产品需求](<../product/requirements.md>) · [当前进度](<../product/status.md>)

| 步骤 | 交接结果 |
| --- | --- |
| 1. 下载 | 通过下载核验的整条原片和来源记录。 |
| 2. 判断 | 整片统一的目标取景、表演人数、姿态和选择理由。 |
| 3. 选图 | SA02 与 BM01 各自的定稿目标图和人员绑定。 |
| 4. 执行 | 各版本的实际工作流、输入、原回执和输出状态。 |
| 5. 交付 | 按各自回执取回的 MP4 和简要结果。 |

## 下载与原片核验

1. Bilibili 保留 BV／av 与链接选定的分 P。X 以帖子中选定的视频为准，抖音以核实的作品页为准。短链按下载技能支持的方式解析。链接或页面能唯一确定目标时继续。若多 P 或多视频确实指向多个合理候选，只问一次选哪个视频。每个选中的视频均以完整文件进入迁移。
2. 用 `/ra-video-download` 下载指定视频，原片和来源侧车保存到项目私有 `media/sources/<source_id>/`。已有原片按实际身份复用。每条链接分别记录来源和结果。素材处理及后续用途按本次任务和适用授权执行。
3. 源片执行下载技能既有的非空、视频流、音频流和时长核验。登记下载方式、SHA256、画幅、帧率与实际编解码信息。缺音频时按下载交接状态报告。纯视频源将在交接能力和 H3 输入都得到验证后纳入。源链接与原始元数据留存于私有资料。

<a name="routing"></a>

## 整片判断取景、人数和姿态

| 判断 | 选择依据 |
| --- | --- |
| 半身 `half_body` | 上身、手臂和手势是主要动作，目标用膝部中景。只拍到腰部以上的源片可以走这条路线。 |
| 全身 `full_body` | 脚步、接地、转身、起蹲或位移决定动作。所需部位要在原片可辨，才能据此选全身路线。 |
| 单人 `single` | 一位主体完成目标表演。偶然入镜的路人按旁观者处理。 |
| 多人 `multiple` | 多位主体有共同表演、互动或队形。整片使用一致的人物绑定，换位时沿用原绑定。优先验证双人。 |
| 姿态 | 当前有 S02 站立图。坐姿或其他姿态先完成下载与判断，再登记需要补充的目标图和工作流。 |

整片观察只给出可见范围、人数、姿态、目标取景和理由。动作解析和迁移交给工作流，禁止人工拆解、抽帧、标注动作时间点或手工指定动作。切镜、换人、人数变化、出框或遮挡导致整片无法归入一条明确路线时，保留完整原片并登记具体原因。时长或其他输入规格超出工作流能力时，按整条视频或对应版本报阻塞。

<a name="target-selection"></a>

## 双角色选图与运行

按同一个整片判定分别匹配 SA02 和 BM01。半身对应 F01 与 F05，全身对应 F02 与 F06。按当前清单和哈希使用正式文件。双人路线使用各版本已配置的组合图或逐人图，每版内保持统一画风并区分两位目标人物。缺少匹配图、映射或工作流时记录受影响的版本，另一版本有可用配置时继续。[定稿图与文件核验](<../assets/reference-images.md#target-frames>)

对重复链接按实际源视频身份复用原片。原片、角色版本、目标图、工作流及实际配置一致时，复用对应版本已取回的 MP4。用户要求重做、调整配置或更换目标图时建立新尝试，保留既有回执和产物。[提交与找回](<h3-4090.md#submission>)

## 直接交付

按每个版本的回执找回工作流输出，存为 `outputs/<run_id>/<item_id>/<variant>/<attempt_id>.mp4` 后直接交付。交付说明写明源 ID、角色版本、整片输入、音轨处理和已知执行限制。取回失败或回执不明时记录该版本的状态与原因。成品跳过校验、人工审查和确认。用户后续指出具体问题时按原任务记录调整或重试。[交付条件](<../verification/acceptance.md#delivery-review>) · [任务模板](<../templates/动作迁移任务与交付模板.md>)
