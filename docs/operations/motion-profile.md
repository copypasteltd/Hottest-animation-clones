# 动作迁移视频画像采集与打标规范 v1.0

画像回答“这条原片是什么、哪些动作在何处可见、每个生成版本实际保留或改变了什么”。**一个批次中的一个完整源片对应一份画像**；同一文件跨批次用 SHA-256 去重，作品身份、分 P／媒体选择记录及批次身份不得合并。画像不作为分段指令，也不把标签送入生成或阻挡交付。不修改既有 [运行记录契约](<run-record.md>) 或媒体文件。

[画像 Schema](<../schemas/motion-video-profile.schema.json>) · [固定标签词表](<../schemas/motion-tags.v1.json>) · [虚构 JSON 示例](<../examples/motion-video-profile.example.json>)

## 数据分层与身份

| 字段 | 采集来源与写入规则 |
| --- | --- |
| `key` | 项目原 `run_id / item_id`；范围固定 `whole_video`。保留文件 SHA-256、大小、相对路径。原片分析可复用，须检查媒体哈希、词表／方法版本和采样口径；作品身份相同不代表文件相同。 |
| `source.identity / capture` | 分开记录平台作品 ID、明确选中的分 P／媒体 ID 和实际源文件。页面未声明分 P 时记录默认入口，不倒推 P1 或 CID。采集时间注明来自下载完成记录或独立快照；发布时间不是采集时间。 |
| `source.platform_fields` | 从已有快照提取标题、简介、作者公开名称/ID、发布时间/上传日、分类、平台原始 tag、平台话题、文案话题、字幕语言、语言、曲目、作者、平台申报时长及互动计数。原始 tag 保留原文、顺序和重复；文案 #话题另存，不当平台原始 tag。字幕只保留语言键，不拉字幕链接；计数仅代表该快照时间。 |
| `source.media / audio_signal` | 本机探测容器时长、编码栅格、旋转、标称/平均帧率、帧数（仅在探测返回时）、比例、编解码、音频声道和采样率；平台时长另存。音频幅度为解码后的测量值，超过 0 dBFS 的浮点峰值并非文件损坏证明。 |
| `source.observations / routing` | 多维标签只写实际证据；已有路线记为执行过的选择，不冒充标签模型自动路由。人数指参与表演者，路人、贴纸或静态图不算。人物编号仅为片内匿名索引。 |
| `renditions[]` | 一个已取回 MP4 对应一行：版本、尝试、源哈希、取回回执和实际文件哈希。历史交付未记录事件时间时，`retrieved_at` 与对应归档回执都保留为 `null`；不采用文件修改时间、渲染完成时间或补档日期代替。已记录的时间仍须符合 RFC 3339 并与回执一致。配置的人物图、S02、运镜相关分支和原音处理与独立观察分开。失败、待取回和停止留在原运行台账。保存历史画像或不同尝试时另存，不替换原始数据。 |
| `renditions[].comparison / acceptance` | 分别评估动作、足部、运镜、场景、音频，同刻是各自媒体零点的名义观察时间。内容验收必须有对应文件的回执/明确记录，点赞式反馈或技术取回不自动算内容验收。 |

元数据字段状态：`present` 有值（计数 0 也是值）；`empty` 明确提供空字符串或空列表；`not_obtained` 当前快照没给或为 null；`unsupported` 仅在有明确能力证据时使用；`not_applicable` 不适用；`invalid` 拿到不合契约的类型/值，原始证据不改。每个字段携带快照证据 ID、JSON Pointer、来源类型。`not_obtained` **不等于平台没有该字段**。保留私有原始快照，不把下载流地址、签名链接、Cookie、原始错误或凭据复制进画像。平台入口仅保留可验证的作品地址和明确选择参数。

## 取证与标签

- 整片先均匀采样，记录名义栅格时点、抽样证据文件、方法和版本；需要辨认手形、接地、短事件时，可在候选附近加密取证。静帧、连续窗口、信号测量、OCR、ASR 和人工／多模态抽审分别注明。未运行的专项模型不补造结果；不安装权重、不向外传原片作默认回退。取证时点不改变整片生成要求。
- 受控词表覆盖内容型态、动作、可见性、取景、运镜、场景、道具、互动、音频、文字和生成质量。机器 ID 与中英显示名分离。同片可有同维度多标签，同一动作可按多条样本组或区间记录。扩展要加词表版本，禁止就地重定义 ID。
- 每条标签记录状态、粗级置信度（高／中／低，非概率）、可选表演者、时间范围、证据 ID 和限制。`observed` 为当前范围的可见事实或明确信号测量；`candidate` 是可能、不能作为确认标签；`not_observed_in_samples` 只陈述所列样本未见。每个维度都标覆盖：抽样、信号、证据不足、未执行或不适用，不用空数组暗示“没有”。看到双手向胸前靠拢，不足以确认比心；仅拿 BPM 或服装不判热舞。
- 时间为媒体零点后的整数毫秒；`clip_summary` 是片级概括并注明抽样，`sample_points` 是证据标记的时点；`estimated_interval` 用左闭右开和时间分辨率，须有落在区间内的样本，不能把同类散点拼成连续发生。重复动作可有多个互不覆盖的同标签区间。解码时钟位置为名义观测，不是逐帧对齐保证。
- 人转身、相机绕行、原地点摇和画面滚转是不同标签。背景侧区运动只能支持目前的屏幕证据；成片地面网格透视变化不代表相机轨迹完全复现。足部静态位置不证明触地动力学或不存在脚滑。音频峰值/周期候选不证明曲风、BPM、歌词、口型或动作踩点。音频相关性仅比较局部搜索内的下混波形，不是码流同一性或唇形评估。
- 证据表按记录内 ID 引用，带项目内相对路径、SHA-256、字节数、所绑定媒体哈希、方法、定位点与采集时钟。验证程序拒绝跨源／跨成片引用、越界及没有对应证据的取样时点。比较证据应包含源和对应成片，不用旧版证据给新版打标。

## 本地保存、复查与公开边界

1. 输入为已核验的原片、下载侧车/快照，以及各已取回版的运行记录和交付回执。现有 Bilibili 快照可离线重提取，不重下。X、抖音允许在契约中记录，本文实现不声称完成这两站的原始快照提取／实跑。动态字段更新另取快照，不改旧快照。
2. 私有画像约定存到 `runs/<run_id>/<item_id>/motion-profile-v1.json`。媒体、证据、真实画像和回执不得入 Git；只发布规范、词表、虚构样例、离线工具与测试。检索时默认用已确认标签；明确查询才包含候选；源片、成片和意图不能合成同一个标签集合。
3. 在项目根运行 `python -B scripts/check_motion_profiles.py <profile.json> --verify-assets`。无 `--verify-assets` 检查结构、词表、引用与时间约束；加该参数复查证据字节、实片与回执、快照投影等一致性。命令不会下载、再生成或改 MP4。公开例子仅是虚构结构演示，不能用作实测证据。

首轮实跑限定现有两条 Bilibili 原片及各自指定的最新两版。使用带时间标记的画面抽样与必要的加密手势局部、历史局部对照、本地音视频探测和波形／周期测量。没有用自动 OCR/ASR 或姿态模型对两片作全量识别，不承诺穷尽动作。生产自动打标、联网采集、界面与索引服务不在本次范围。
