# 动作迁移运行与交付规范

适用于 [链接到基准白模视频 v0.4](12-项目需求梳理与实现方案总纲.md)。此处定义实际接线需要核对的输入、路由、回执与交付字段。结构示例为离线文档样本。[运行记录 Schema](schemas/motion-transfer-run.schema.json) · [虚构记录](examples/motion-transfer-run.example.json)

## 1. 链接与原片

1. 支持 Bilibili 作品、X 带视频的帖子和抖音作品。核实目标作品与视频选择，保留 Bilibili 分 P 等内容选择字段。X 帖子多视频且目标不明时登记待复核。
2. 下载调用已安装 `/ra-video-download`。工作目录与素材输出目录位于本项目，调用技能时以项目内私有 `media/sources/<source_id>/` 为指定输出。依赖使用该技能已核验的原生 Windows 工具链，已有文件按技能规则复用或另存。
3. 保存实际下载方法、视频相对路径、大小、SHA256、时长、画幅、帧率及音视频流。按下载技能的交接要求核对实际视频流、音频流和有效时长。缺少音轨或交接未通过时登记具体探测结果，按技能实际返回状态处理该项。原片及来源侧车集中留在私有素材目录。
4. 来源证据按下载任务授权保存。确认外部用途时区分素材来源权利、本项目获准处理范围和成片发布权。处理仅针对用户交来的作品。访问限制或认证不足由下载技能报告，保留有效失败结果。

## 2. 判断与选图

| 判断项 | 依据和记录 |
| --- | --- |
| 动作区间 | 默认覆盖原片中的完整连续表演。用原片时间戳记录主要动作的半开区间与关键事件，使用毫秒。按开头、核心动作和结尾留证，快速动作或遮挡区间连续回看。分段或受模型时长限制时，记录调整原因、实际范围及未处理部分。 |
| 半身／全身 | 先写原片哪些部位真实可见，再依据关键动作选择目标取景。半身优先服务手势与上身。全身要求检查足部、接地、位移或转身。全身原片里的纯上身动作可使用半身图。 |
| 单人／多人 | 记录参与动作的主体数及其区间。多人保留相对站位、交互和对应，临时路人按非表演者记录。 |
| 姿态预设 | 当前素材覆盖站立 S02。坐姿等片段使用对应姿态预设，沿用取景与人数判断。缺少当前姿态的预设时记录具体阻塞项。 |
| 目标图 | 读取当前角色和构图清单，按项目角色预设、姿态、取景和人数匹配，核对版本及文件哈希。多人按真实输入位绑定组合图或逐人目标图并记录对应。 |

源片可见范围和目标构图分别记录。比如把只拍到腰部的单人手势套用到膝部中景，源观测写腰部以上，目标为半身膝部构图，审核只覆盖有证据的动作。核心动作所需的手脚一直不可见、多人对应不明或素材跨镜时，标出需复核区间或可单独执行的范围。

判断用 `half_body`／`full_body`，人数用 `single`／`multiple`，证据不够用 `needs_review`。选图时使用已匹配的当前资产及既有审查规则。单人映射是 SA02 F01／F02、BM01 F05／F06。缺对应多人资产时，记录目标图缺失并阻塞该路线。成片要求写实或二次元时，角色和媒介以项目预设和实际目标图为准。[S02 构图与文件](17-S02场景定稿与四张构图母版规范.md) · [SA02](16-SA02二次元角色使用约束.md) · [BM01](19-BM01真实角色替换与JK03退役约束.md)

## 3. 4090 工作流

1. 在指定 4090 的 ComfyUI 根下读取 `user/default/workflows/社区精选H3_人物与场景替换_实验`。逐路线记录实际文件、哈希、活动分支和节点输入。配置中的路径相对远端 ComfyUI 根解析。工作流可覆盖一个或多个取景／人数组合，覆盖以可验证的输入、输出和样片为准。
2. 确认运动参考视频、目标图、人数对应、音轨、时长、画幅和实际帧数的支持方式。只有一个目标图槽时，将人物与 S02 同图的构图母版作为待验证的输入组合。将实际连接、输入角色和样片条件记入路线配置。若使用独立场景输入、多张参考图或多人图，逐路线核实节点映射及实际出片。浏览界面的图与 API 执行图版本关联保存，使用实际可提交且校验过的格式。
3. 源视频提供动作与节奏，目标图提供所选角色的外观和 S02 构图。登记每项输入后提交一次，记录所用文件标识、工作流版本、实际参数与任务回执。重采样或分段带来的范围和时间差异记入回执。已有队列任务按原 ID 观察。未知提交结果保留 `unknown` 并继续核对原队列、历史和输出。
4. 接线验证先确认活动分支、节点、模型、目标图和输入规格，再提交匹配的样片。样片通过媒体、人物、场景和动作检查后启用该路线的常规链接任务。接线条件缺失时记录具体原因。单人和多人各取景组合分别登记验证结果。[H3 历史样片](evidence/H3基础用例公开摘要.md) · [路线验收](14-实施计划与验收矩阵.md)

## 4. 成片与交付

- 在本地 `outputs/<run_id>/<item_id>.mp4` 交付通过的成片。实际处理使用输出能力明确的容器配置。保存播放／解码、尺寸、实际时长、视频流、音轨处理和哈希。画幅与帧率按实际工作流和目标构图记录。
- 按关键事件核对动作顺序及节奏，检查目标人物外观、所需手脚、接地或互动、动作出框和 S02 背景。多人复核参与者对应与相对关系。脚步、指尖或音画同步有局限时，标明证据与可用范围。音轨按已选方式验收。
- 每项记录处理状态与质检结论。处理完成表示输出已取回且通过媒体探测。作为成品交付还需要该项视觉与动作质检通过。待审、失败或阻塞项在批次中给出直接原因和有关文件。
- 区分原片、远端回执、候选和成片。本地私有 `runs/<run_id>/` 保存机器记录，详细审核与提示词在 `docs/runs/<run_id>/`。交付说明使用源 ID，来源链接和详细元数据留在私有素材侧车。[目录规则](15-项目路径结构与开源维护规范.md)

## 5. 每项运行记录

| 字段 | 要点 |
| --- | --- |
| `source` | 平台、来源 ID、下载状态、实际文件和媒体探测摘要。 |
| `decision` | 可复查的时间点、源可见范围和人数，计划取景与姿态，动作范围、理由与限制。 |
| `target` | 选图对应和版本、目标图哈希、实际审核状态。 |
| `workflow` | 固定目录内的已核对工作流引用，哈希、活动分支、有效输入映射与观察状态。 |
| `execution` | 处理状态和原因、尝试 ID、实际输入和参数清单路径、原始提交回执。 |
| `output`、`review` | 通过媒体检查的交付候选及其文件信息，视觉与动作审核证据和结论。 |

可用状态按单项记为 `planned`、`blocked`、`running`、`unknown`、`failed` 或 `completed`。批次汇总按源 ID 和执行区间计数。Schema 核对字段结构和状态关系，实际执行还需校验区间边界、证据时刻、文件身份与多人对应。修改目标图、路线、区间或工作流后形成新尝试，保留原输入和回执。用 [执行记录模板](templates/动作迁移任务与交付模板.md) 核对具体运行。[虚构记录](examples/motion-transfer-run.example.json)
