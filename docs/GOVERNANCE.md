# 项目维护与决策规则

## 当前阶段

项目采用specification-first方式：需求基线v0.3，仓库基础包版本0.0.1。用户已指定GitHub目标copypasteltd/Hottest-animation-clones并授权正常推送及后续同步；维护者名单、服务承诺和正式版本发行仍未假定存在。

## 决策优先级

1. 业务目标与来源/隐私边界。
2. 数据契约、版本与独立审核语义。
3. 可观察的验收和真实样本证据。
4. 具体工具、模型和实现便利。

具体工具不能反向要求删除不利样本或把生成轨迹改成源真值。详见[总纲](12-项目需求梳理与实现方案总纲.md)。

## 变更与发布

- 需求用稳定ID追踪，新增/变更同步TC、Schema、样例和版本失效规则。
- 争议写入Issue/PR的范围、理由与证据，未验证的假设明示，不以模型自述当通过。
- 需求基线版本与软件版本分别管理，不因文档v0.3就发布实现v0.3。
- 维护者审阅后合并main，先文档/单测通过，再进行单独授权的模型实测。
- 数据/工作流资产的公开需独立权利核查；代码发布不能代替数据许可。
- 用户已指定远端与持续同步授权，遵循[发布规范](18-开源发布与持续同步规范.md)和[AGENTS](../AGENTS.md)更新双语README/媒体/说明、检查后正常push；新指令可暂停。force-push、删除历史与正式发行不在默认授权内。
