# 开源发布与持续同步

公开项目位于 GitHub，目标分支为 `main`。同步内容限于明确授权的变更。项目维护约束规定开发范围及用户的同步要求。[GitHub 仓库](https://github.com/copypasteltd/Hottest-animation-clones) · [维护约束](<../../AGENTS.md>)

<a name="display-assets"></a>

## 公开范围

公开内容包括项目原创文档、维护源码、测试、无敏感配置示例、虚构记录和脱敏实验摘要。媒体只允许两份 README 内嵌的八张既有 PNG 字节一致副本，以及对应的展示清单。清单记录发布时的文件路径、状态、尺寸和哈希。资产页记录现行定稿用途，发布检查核对图像身份及双语内嵌引用。[展示清单](<../images/characters/manifest.json>) · [人物与构图状态](<../assets/reference-images.md>)

视频库 v1 只把经明确白名单审核的前端源码、锁文件、测试与虚构夹具生成器纳入 Git。公开示例与本机私有预览隔离，生成站点、截图和私有媒体均不入 Git。源码同步不扩大媒体许可，也不代表批准部署。[构建与验证](<../operations/motion-catalog-frontend.md#run-catalog-v1>)

实际源片及侧车、正式资产清单、设备和模型配置、上游工作流、凭据、运行回执和生产成片留在项目私有区域。媒体授权与第三方许可按用途核对。[目录规则](<workspace.md#layout>) · [第三方材料](<../THIRD_PARTY_NOTICES.md>)

<a name="task-classification"></a>

## 新任务归类与自动同步

每次在本项目接到新任务时，先按请求目的归类，再按对应规则执行与归档。同一请求涉及多类时，分别判断结果的公开范围。此规则随任务执行，不设置后台定时同步。

| 类别 | 归档与同步 |
| --- | --- |
| 新媒体任务 | 按现有规则新建或追加批次，核对原片、可见取景和人数、版本与实际回执。原片、成片和取证留本地；只有可公开的脱敏案例或能力变更才更新公开文档。 |
| 重做、修复或验证 | 关联原片、原批次与目标版本，新生成时另记尝试。保留旧结果。区分已取回、已检查和内容已验收，不把样本改善写成全程保证。 |
| 资产、工作流、代码或文档维护 | 按类别更新对应说明、源码或测试。正式素材和设备配置仍私有；提交前核对公开白名单和可复现事实。 |
| 只读查询或检查 | 在回复或已有私有记录里给出结论和限制；没有可公开的变更时不造空提交。 |

本项目后续任务的公开变更通过下列检查后，默认正常推送至授权仓库的 `main`，并核对远端提交，不必逐次请求推送。没有公开差异则不推送；暂缓或先审阅的明确要求优先。不要把任务请求当作公开媒体、部署或扩大权限的授权。

<a name="sync"></a>

## 提交与远端核对

1. 查看工作区、已暂存内容、当前分支和实际远端引用，保留其他本地工作。远端发生变化时先获取并比较历史。
2. 同步受影响的中文和英文入口、权威主题页、示例与验收项。在双语变更记录写明实际覆盖及待验证的运行能力。
3. 运行本地文档检查、发布检查和单元测试。按精确路径暂存已审阅变更，再运行索引保护及差异检查。
4. 仅提交本任务已审阅的公开变更，按长期授权自动正常推送。用远端 `main` 的实际提交核对同步，CI 结果独立登记。遇到网络、认证或远端历史冲突时保留本地提交和具体诊断。[维护命令](<workspace.md#offline-checks>) · [贡献流程](<../CONTRIBUTING.md>)

```bash
python scripts/check_repository.py
git diff --cached --check
git diff --cached --stat
git ls-remote origin refs/heads/main
```

前端、预览部署、正式版本发行及额外公开媒体的范围按用户的明确要求确定。用户提出先审阅或暂缓同步时依其最新要求执行。[治理规则](<../GOVERNANCE.md>)
