## 1. 实施策略与决策门

2026-11-14状态补充：用户已定稿SA02与JK03的正面全身静态锚点及纯白背景，见[角色使用约束](16-定稿角色SA02与JK03使用约束.md)。随后用户已定稿S02场景，静态膝部/全身4张组合图已生产并查看，见[场景与构图母版](17-S02场景定稿与四张构图母版规范.md)。这完成了选型与静态组合生产，不等于M0模型/预算全部结束，也不等于任一动态TC通过。后续按两条独立角色与选定场景执行，不重新随机选角/景。

先以少量素材证明双分支数据正确、手势可读，再验证标准视频没有让下游动作更差，然后扩大规模。不要在角色/场景和动作保持未验证前大量生产白模视频。

## 2. 样本与人工基准

### 2.1 样本分组

校准集6–10条用于调模板/阈值/模型，不参与最终质量通过率。试产冻结集建议10个来源实例：6个核心正样本＋4个压力/反例。两集按来源表演组分开，镜像、裁切、转码和变速不得跨组泄漏。

核心正样本要事先满足用户希望支持的scope和可观测性，建议覆盖简单挥摆、交叉展开、交替指向、关键手型、快速翻腕、全身脚步/转身。至少包含2个动作家族各有2组确认独立表演来源，数量不足则先补采，不用转载凑多源。

压力/反例建议覆盖：双手长遮挡、半身却要求脚步、快动作模糊、镜头/人物切换或镜像未知。允许一个样本含多个条件，但报告实际条件分布。反例不要求生成成功，要求正确未知/降档/拆段/退回，不把假补点当成功。

若冻结前无法取得指定数量，应显式修订样本计划，不声称测试覆盖已经达到。冻结后失败样本保留原结果；新增版本重新评估，原测试记录不擦除。

### 2.2 人工基准

- 每个实例冻结核心/上下文、required事件、关键手指/掌面/双手关系、顺序和事件锚点。
- 从各条件抽约100–200帧人工标可见身体/手点作为提取器校准与评估；被遮挡不标虚构坐标。
- 采样记录源时刻，快手势区间用连续回放/更密帧，稀疏首尾不能确定中间动作。
- 冻结至少10个检索题，含同义表达、硬条件、负例和同身体不同手型；开发题与最终题分开。
- 核心手势与A-B评审建议两人独立；分歧保存并裁决。资源只有一人时允许单人两轮做研发探索，但完整对外验证需标其证据限制，不能声称独立双人一致。

## 3. 指标、门槛与通过约定

### 3.1 所有阶段的硬检查

| 检查 | 口径 | 要求 |
|---|---|---|
| 来源与终态 | 每个输入都有源身份/处理结果/失败原因 | 100% |
| 轨迹结构 | shape/点序/坐标/单位/时间/mask/变换可读 | 100%；结构错误隔离不发布 |
| 观测来源 | source与generated轨迹不混源，实际/计划/推断分开 | 100% |
| 时间合法 | 区间、核心/上下文、单调映射、音视频起点 | 100%；生成锚点缺失不能编造匹配 |
| 发布门禁 | 所有required维度passed且文件hash/引用有效 | 100%；not_applicable不得绕required |
| 完整性 | 清单present文件存在、媒体可解码、备份可验证 | 100% |
| 边界 | 本地仅项目、文档仅docs、外部目标按任务授权 | 100% |

### 3.2 拟议质量线：校准后冻结

| 指标 | 计算方式 | 初始目标/处理 |
|---|---|---|
| 身体定位 | 可见身体点PCK@0.10，归一化尺度为人工肩宽；重复腕不双算 | 清晰组≥90%，另报像素误差和不可评估率 |
| 手部定位 | 可见手点PCK@0.15，尺度为人工腕到中指MCP长 | 清晰组≥80%；初始目标而非已验证通用阈值 |
| 有效手部覆盖 | 实际可见且足够像素的required手帧中，≥18/21点有效的比例 | 清晰组每所需手≥90%；score阈值/最小像素先校准 |
| 决定性事件 | required指尖/关系在事件锚点及必要过程能核实 | 全部可判断且正确；关键缺失不能借总体覆盖通过 |
| 左右身份 | 核心事件中的解剖/屏幕手身份不混淆 | 获批scope无未解决关键切换，镜像未知保留 |
| 语义与家族 | 人工required标签准确、家族核心一致 | 各≥90%；未知单报、不当准确标签充数 |
| 视觉与对齐 | 角色/场景/必要部位稳定，required事件/顺序/手型，时间误差 | 按每动作pass_contract，所需事件全部通过 |
| 检索Hit@5 | 冻结问题中Top5含至少一个可接受定义及实例 | ≥90%，硬条件符合率100% |

PCK不可评估的帧/点要报告且保留困难分组，不能删掉改善分母。骨架分数是检测/模型估计质量，不自动验证生成动作。手腕与手指缺失时不通过“精细双手”scope，可发布明确身体范围。

每个动作的时间容差应基于事件与节奏在校准时冻结；例如一次点指的锚点与持续摆动的容许范围可能不同，当前不硬套统一150ms。尚未给出具体可计算容差的动作，不进入严格对齐通过集。

### 3.3 pass_contract必填表

| 类别 | 需要预先冻结的内容 |
|---|---|
| 对象与scope | definition/occurrence/eventset/角色/场景/模型固定版本，full-body或upper-body、所需左右手 |
| 动作语义 | 必需事件、手型/掌面/双手关系、顺序、禁止新增/颠倒 |
| 时间 | 原速/允许伸缩、源与目标时长、每事件锚点及容许误差、前导/补尾规则 |
| 画面 | 身份要素、服装、场景、必要部位边界、允许相机变化与不可接受漂移 |
| 缺陷 | 额外/缺失/融合肢体、关键手势不可读、身份漂移、跳场、出框等失败条件 |
| 未知与证据 | 关键不可评估判needs_review/failed，允许not_applicable的项及scope依据 |
| 方法 | 人工/自动指标、比较坐标前提、评审者/裁决、样本与阈值版本 |
| 预算 | 每分支/每样本尝试次数、GPU时间/费用/磁盘上限，取消与资源降级策略 |

passed必须符合所有required项，不是加权平均分抵消缺陷。运行success、视频可播、原音hash相同、动作准确四个结论分开。

## 4. 下游A-B验证与误差累积决策

### 4.1 矩阵

- 路线A：原动作片→目标角色。
- 路线B：同源标准角色白模动作片→同一目标角色。
- 首版至少选择2个目标角色，建议写实与风格化人形各1。
- 核心冻结组建议6个实例×2目标角色×2路线×1预设尝试＝24个下游样本；标准片生产为另一个阶段，不混计次数。
- 初始预算不足可先做2实例×2角色×2路线＝8个探索样本；这不等于完整6实例覆盖，正式目标调整必须发生在最终冻结前。
- 同模型、同模式、相同目标规格、可比提示和预算；种子可控制时配对，不可取得时记未知。两路线原本使用不同motion输入，需记录这种差异而不是假称条件完全相同。

### 4.2 判定

1. 源→标准片的动作保持先通过，才进入作为正式参考的B路线；失败标准片可以做失败分析，不当合格B输入。
2. A/B盲化模型/路线标签评审required事件、顺序、手型、时间、身份及源外观/背景泄漏。
3. B的核心事件不能相对A新增丢失/颠倒/错误，且双方都需达到预定动作保持scope；A失败不意味着更差的B能算通过。
4. 定义非劣容差（如时间偏差、人工修订量）和希望改善的指标（外观泄漏、检阅/上传便利、成本）后再跑。至少核心动作不明显变差，并在预设用途上有实际收益或达到明确容差内的同等可用。
5. 报告所有尝试、失败和最终选用，不只展示最佳种子。试验重跑与新增样本记录版本。
6. 不通过时保留原片＋合格源骨架，将标准视觉标待修/非优选，不批量认证。可改模板/模型、人工修正或另立3D路线，但不继续生成多代素材充源真值。

## 7. 资源与成本记录

每attempt记录输入秒/帧、设备与模型精度、分辨率、提取/生成/编码耗时、CPU/显存/内存峰值、磁盘、人工审核分钟、外部费用和重试原因。RTF=处理墙钟秒/输入秒，仅在该配置实测后使用。

批量决策依据：每获批动作/每有效骨架分钟/每可用生成秒的真实成本，而不是单次调用最低价格。源文件、预览、raw/repaired/normalized、模型权重和生成各自统计；相同内容可去重但不销毁来源引用。

试产前写resource_budget；预算不足允许缩小探索批次，但不能在最终评估后删失败来满足验收。当前无可靠GPU/模型/审核吞吐数据，不承诺实时或固定总工期。

## 8. 文档交付与验收记录模板

每个TC执行记录：case_id、需求编号、样本/配置/契约版本、输入hash、设备、命令或人工步骤、实际输出、passed/failed/needs_review/not_run、证据文件、评审者及修复指向。

公开文档完整性由仓库维护脚本校验：需求编号唯一与连续、全部需求有TC、TC无未知引用、本地链接存在、JSON样例/Schema结构与负例。运行方式见[维护规范](15-项目路径结构与开源维护规范.md)。真实轨迹、媒体、独立审核和源时间属于未来产品测试；本地生成的报告不进入公开源码仓。这不是上述29个产品TC已经执行通过。
