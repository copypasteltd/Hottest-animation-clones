### 2.2 不允许覆盖v1

- 同名PNG被修改或替换，即使人眼很像、人物名相同、参数相同，也不是这个v1锚点。
- 改脸、发型、服装、媒介、比例、背景规格或锚点文件，必须另建v2并说明变化，经过用户明确批准后才能变成当前版。
- 资产清单、selection和校验程序的固定hash也不能作为“修复哈希”静默更新。若确需改，保留v1并新增决策版本。
- 缺文件、hash不符或读取失败时**停止**，不偷偷回退到候选图、官方设定图、旧轮次、重生“相似人物”或另一个角色。
- 图片已独立复制，候选目录改名不会改变正式锚点；仍保留来源引用供审计，不依靠重跑生成复原它。

## 5. 动作迁移中允许与禁止的变化

允许：任务指定的动作/姿态、自然动作所需表情、头发与衣物在运动中的合理小幅变形。动作来源负责动作顺序与时序，不负责脸、发型、服装或角色媒介。

默认不允许：换装/换脸、原舞者外观和房间泄漏、画风改变、人物体态明显变化、额外人物/道具或脚手出框。动画SA02不能被真人动作参考带成真人，写实JK03不能被动漫参考带成动漫。

人物v1主锚点仍为**纯白无场景背景**。用户之后已明确选定S02：纯白背景＋浅灰网格地面，并授权膝部中景/全身4张组合图，具体按17单独固定scene/framing版本，不回写人物v1。其他房间、绿幕、墙面网格或道具仍须另获批准，不能从旧总纲建议推定。具体舞段仍需按幅度保留抬臂、横移和脚步空间，不为套原图构图而裁掉动作。

源片/源骨架可以照常从原始舞者提取，但不能因为已选角色就把生成片轨迹替代源轨迹。静态角色通过不代表身体/双手动作、踩拍或服装连续性已通过。

## 6. 衍生图与新版本规则

1. 本轮只有正面全身主锚点，面部近照、侧面、背面和细节图均未制作/未获确认。
2. 后续补图只参考对应角色的v1主锚点，不串联“侧图生成背图”等多代漂移路径，不混入另一个角色参考。
3. 图片中未出现的背面花纹、鞋底、发后结构等记unknown，不能凭想象写成已批准设计；新补图先为candidate，用户确认后才成为supporting_view。
4. 单纯等比缩放/模型规格适配作为派生输入另存hash和变换，不覆盖锚点；裁切不得默认丢掉必要部位，格式/尺寸不兼容应报告。
5. 改锚点或服装/画风需新revision与用户确认。相关视觉、衍生视图、对齐、参考包及目标模型结论失效/待复审；原片和无关source pose不因此重提。
6. 角色选型不指定未来必须使用原出图模型；下游模型可按任务选择，但能力/媒介不兼容时必须报告，不得静默降级。本篇首次冻结本身未授权额外任务；用户随后明确授权的S02四图任务按17记录，仍不包含视频生成。

## 7. 生产使用前检查

已提供本地只读校验入口：[check_character_lock](../scripts/check_character_lock.py)。从项目根执行：

```bash
python scripts/check_character_lock.py
```

检查selection固定hash、两条asset清单hash、锚点hash与PNG尺寸、独立角色身份、用户确认范围和未验能力标记。若本地资产未提供（例如干净开源克隆），显式报告缺失，不自动下载或替换。

**执行范围说明**：此脚本只做文件/元数据一致性，不能自动判断视频换脸、服装漂移或动作精度，也没有建立操作系统级不可写权限或通用防篡改隔离。当前视频执行器尚未集成这个检查；后续每次实际任务需要先显式执行并记录结果，再由人工看输出。不能把本篇约束存在称为所有生成已自动受控。
