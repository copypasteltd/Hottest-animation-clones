# 产品需求 · 整段视频双角色动作迁移

需求基线 v0.5。用户提供 Bilibili、X 或抖音作品链接。每条链接选中的完整参考视频默认生成两份 S02 基准白模 MP4，**SA02 二次元一份，BM01 写实一份**。两份都使用同一份完整原片，各自提交和取回。[当前进度](<status.md>)

## 五步需求

| 需求 | 项目负责 | 交接结果 |
| --- | --- | --- |
| R-01 | 通过 `/ra-video-download` 下载链接选中的完整参考视频。 | 已完成下载核验的原片和私有来源记录，或可定位的下载结果与原因。 |
| R-02 | 对整条原片判断半身／全身、单人／多人和姿态。 | 整片的取景、人数、姿态和选用理由。 |
| R-03 | 按取景、人数和姿态，分别为 SA02 与 BM01 选择已定稿的 S02 替换图。 | 两个版本各自的目标图及其文件身份。双人路线另有对应的人物与组合图配置。 |
| R-04 | 将整条参考视频与对应的目标图提交给指定 RTX 4090 的 H3 工作流。需要接线调整时在工作副本上完成。 | 两个版本各有实际工作流、输入、提交回执和可取回的输出，或具体状态与原因。 |
| R-05 | 按原回执取回工作流输出并直接交付。 | 每个取回的版本有本地 MP4 和简要说明。未取回的版本有可追溯的状态。 |

## 整片处理与选图

- Bilibili 分 P 和 X 帖中视频的选择用于确定原片。原片确定后，完整文件就是执行输入。工作流负责从原片获得运动与节奏并完成迁移。人工判断只用于选路线。禁止人工拆动作、抽帧标动作或手工指定关键动作。
- 同时适合半身和全身时优先保证主要动作易读。上身和手势为主用半身。脚步、接地、转身或位移也决定表演时用全身。人数按实际参与表演者计算，姿态按整片的表现和可用配置判断。
- 站立单人沿用既有定稿母版。半身使用 SA02 F01 与 BM01 F05，全身使用 SA02 F02 与 BM01 F06。多人先覆盖双人。两个版本各使用同画风、可区分的目标人物，维持整片人物对应。[S02 与定稿图](<../assets/reference-images.md#target-frames>)
- 遇到关键可见性不足、身份对应不清、未配置姿态或工作流无法覆盖完整原片时，登记整条视频或受影响版本的原因。禁止将参考视频拆段、剪短或将部分动作作为交付替代。

## 交付与重跑

从原回执取回对应 MP4 后直接交付，跳过成品校验、动作或画面审查及人工确认。简要说明含源 ID、角色版本、整片输入、实际音轨处理和已知执行限制。一个版本先完成时即可交付，另一版按实际状态保留。相同原片、版本、图、工作流和实际配置可复用已取回的结果。用户后续点名哪一条或哪一版调整或重试，就为该版本另记一次尝试。[运行记录](<../operations/run-record.md>) · [提交与找回](<../operations/h3-4090.md#submission>)
