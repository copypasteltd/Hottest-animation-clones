# 项目路径结构与开源维护规范

版本：v0.3，2026-11-13。关联：[项目需求](12-项目需求梳理与实现方案总纲.md)、[数据契约](13-双库数据契约与Skill执行规范.md)。

## 1. 设计原则

**未经用户明确指示并给出相应要求与约束，不得新增前端开发项、交互页面、Dashboard或预览服务。** 整理文档、录制内容和公开仓库的任务不包含自行开发界面的权限。已移除此前额外创建的前端及相关产物。

一个项目根同时容纳可公开源码和本地数据，Git只跟踪审阅后的维护源码、文档和虚构数据契约示例，没有前端或公开演示媒体例外。根据用户2026-11-14的新要求，根目录新增[英文README](../README.md)、[中文README](../README.zh-CN.md)与[项目协作约束](../AGENTS.md)，替代先前不放根README的约定；详细说明仍集中在docs下。包元数据指向根英文入口。

历史实验不搬迁、不删除，避免破坏原结果链接；它们被忽略，不进入公开提交。通用脚本进入scripts，现有设备专用tooling保留本地。用户已明确指定GitHub目标和持续同步要求，正常提交/推送按[发布同步规范](18-开源发布与持续同步规范.md)执行；不强推、不发布未授权包或真实媒体。

空数据目录不靠.gitkeep提交；克隆后运行bootstrap_workspace脚本重建。未来需要发布可复用工作流时，先脱敏并核许可，再显式新增独立公开样例目录与跟踪策略，不把本地workflows整棵放开。

建议未来生产模块：domain、contracts、ingest、annotation、pose、canonical、review、catalog、export、execution、adapters。当前仅设计职责，不批量创建无行为空模块冒充已实现。

## 3. 跟踪范围

| 内容 | 默认策略 | 原因 |
|---|---|---|
| 当前需求12/13/14、角色文字约束16、模板、汇总Schema与虚构样例 | 跟踪候选 | 可独立审阅，不随附真实媒体；角色锁本地检查需另提供资产 |
| 公开首页、维护/安全/治理/第三方说明、脱敏事实摘要 | 跟踪 | 便于社区协作，暴露证据限制 |
| 通用源码、测试、维护脚本、配置example、CI | 跟踪 | 可从干净克隆复查 |
| 旧01–11文档及研究快照 | 本地保留、默认忽略 | 含本机路径/历史链接与未统一范围，不作为当前公开基线 |
| 原视频、角色图、骨架数组、生成结果、模型、工作流实作 | 忽略 | 数据权限、体积与设备耦合；不默认拥有再分发权 |
| docs/runs、旧校验报告、tooling、.local | 忽略 | 私有过程记录、机器路径和局部配置 |
| 真实密钥、设备配置、私网IP/用户路径 | 禁止提交 | 减少凭据和基础设施信息外泄 |

.gitignore是防误跟踪，不是安全隔离。`git add -f`可以绕过它；check_repository检查索引路径/文本作为第二道保护，也不是完整安全审计。推送前仍人工检查diff，凭据若泄漏必须撤销/轮换，不能只删新版本文件。

## 4. Git与分支规范

- 独立仓库根就是当前项目根；默认主分支main。
- 保留本地已建历史，通用项目身份只作用本仓，不读/改全局Git配置；origin按用户指定绑定`git@github.com:copypasteltd/Hottest-animation-clones.git`。
- 维护过程为隔离项目外Git配置，使用项目内.local下空配置作为GIT_CONFIG_GLOBAL并设置GIT_CONFIG_NOSYSTEM=1；初始提交使用通用项目身份，不伪装用户个人。
- Git配置与initial commit只作用于本仓；无需自动开LFS，数据默认根本不入Git。若以后要分发授权大资产，应单独决定数据托管/许可和LFS，不先把历史二进制塞入仓库。
- 新工作使用feat/、fix/、docs/、chore/前缀分支，PR关联需求编号和TC。main保留可运行文档/测试基础。
- 建议提交类型：docs、feat、fix、test、chore；每次提交只做一类可解释变更，需求/Schema/示例/测试同步。
- 用户已要求后续明确范围内的项目变更同步README/更新说明并正常push至指定origin，具体按18执行；不得为此擅自创建前端或演示页面。若用户要求先审阅或暂不推送，以新指令为准。禁止force-push、删除未知远端历史或未经授权发布tag。

## 5. 本地维护命令

以下命令从项目根执行，命令参数中的路径是执行入口，不是文档链接：

```bash
python -m pip install -e ".[dev]"
python scripts/bootstrap_workspace.py
python scripts/check_project_docs.py
python -m unittest discover -s tests -v
# 显式选择本轮审阅后的源码/文档再暂存，避免对真实数据使用强制添加。
git diff --cached --stat
python scripts/check_repository.py
git diff --cached --check
```

安装开发依赖需要联网/已有包；本机可使用已具备的jsonschema，不强制安装或改全局环境。CI在一次性runner只安装Python开发依赖并检查文档/维护代码，不安装前端工具或启动预览服务。具体运行结果以每次提交的实际记录为准。

check_project_docs只校验公开文件、46项需求与29个计划TC、JSON结构和10个负例；不读本地媒体/历史设备日志，不生成报告污染提交。check_repository只读Git索引，报告命中文件和规则，不输出凭据原文。

## 6. 首次开源发布前

1. 确认实际版权/许可证归属；当前MIT仅覆盖本项目原创代码和说明，第三方媒体/权重/源码不在仓中。
2. 在干净克隆验证文档链接与测试，不能依赖未提交的本地报告和媒体。
3. 检查tracked paths、diff及提交历史，无账号密钥、私网设备、用户目录、视频或权重。
4. 明确仓库仍为specification-first，未实现姿态推理/白模批处理/生产skill，不用规划数量冒充实测。
5. 用户已指定目标仓库和推送授权；每次提交前先核对refs和权限，正常push后比较远端main与本地HEAD，具体CI与同步结果另存实际回执，不预填成功。
6. 真正完成实现后才发行v0.1.0等功能版本；0.0.1只表示维护基础骨架，不代表需求v0.3已实施。

## 7. 保持原有路径可用

既有实验媒体、运行报告和tooling留在原位。公开主文档只链接仓内公开摘要，不依赖这些忽略项。旧报告仍可本地打开；提交边界改变不删除数据、不改变原H3工作流、不重启设备服务。

本规范只记录结构和维护约定；本轮实际Git/提交/检查结果由完成消息和本地维护回执说明，不在尚未执行前预写成功。
