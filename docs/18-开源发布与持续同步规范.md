# 开源发布与持续同步规范 / Publication and update synchronization

目标仓库：`git@github.com:copypasteltd/Hottest-animation-clones.git`；[GitHub项目](https://github.com/copypasteltd/Hottest-animation-clones)。主分支`main`。本篇记录用户的正常同步要求，不预填尚未完成的push或CI结果。

## 1. 实施范围 / Explicit scope

**未经用户明确指示并给出相应要求与约束，不得构建任何前端开发项。** 不自行创建网站、交互页面、演示工作台、Dashboard或静态预览服务。整理代码、完善README、录制内容、发布仓库以及“继续项目”均不构成前端开发授权。

**Do not create a frontend without an explicit user instruction and its requirements/constraints.** Documentation, recording and repository-publication requests do not authorize inventing a UI. The previously added frontend, its preview server and associated captures have been removed. Repository synchronization does not expand implementation scope.

当前公开范围：原创维护源码、需求与数据契约、双语说明、纯虚构机器可读样例和测试，以及用户本次**明确要求在中英README中展示的8张既有SA02/BM01静态图副本及manifest**。这项明确的README展示授权优先于先前一刀切的“角色媒体不上Git”默认规则，但不授权其他图片或前端，也不改变角色/构图批准状态或许可证。

## 2. 每次变更必须同步什么

| 变更 | 必须同步 |
|---|---|
| CLI/安装/依赖/目录 | 中英README、使用长文、配置、测试、更新说明 |
| Schema/动作字段/审核/版本规则 | 契约、样例、相关测试和影响说明 |
| 实现进度/模型能力 | 两语言状态表和路线图，区分实测与待实现 |
| 角色/场景/实际任务产物 | 本地版本/hash/批准记录；仅1.1节精确8图可按本次要求复制展示，不覆盖v1或放行其他媒体 |
| README展示副本 | 双语README内嵌8图、图旁状态、manifest、精确PNG签名/尺寸/hash及Git索引检查同步；不改变批准状态 |
| 任务范围 | AGENTS、README与相关规格；新增功能必须来自明确要求 |
| 发布/远端更新 | CHANGELOG、提交、正常push，核验远端commit；CI另查 |

Synchronize both language entries, relevant specifications, examples, tests and release notes. Preserve unrelated local work. A newer user instruction to hold a push or request review takes precedence. Do not add a feature just to decorate its documentation.

## 3. 检查与正常提交

```bash
python -m pip install -e ".[dev]"
python scripts/check_project_docs.py
python scripts/check_release.py
python -m unittest discover -s tests -v
git add -- <reviewed-paths>
python scripts/check_repository.py
git diff --cached --check
git diff --cached --stat
git commit -m "chore: describe the authorized change"
git push origin main
git ls-remote origin refs/heads/main
```

检查核验文档/代码边界及本次README展示例外的精确8PNG签名、尺寸、SHA256、manifest、索引路径和双语内嵌引用，不运行模型或评估真实动作；实际结果以执行记录为准，不能在运行前声称通过。公开克隆含显示副本但缺角色锁所需完整私有文件时仍应明确失败，不自动下载、生成或复制成伪正式资产。首次依赖安装可能联网；后续检查在本地完成。维护任务不启动浏览器或预览服务。

## 4. 远端差异与失败

- 推送前检查refs，远端变化先fetch/比较，不force覆盖历史。
- SSH传输不打印私钥或token；缺权限、认证或网络时保留本地提交并报告具体错误，不假称同步成功。
- 正常push后比较本地HEAD与远端main；CI状态另查，排队不算通过。
- CI失败则修复并新增提交，不通过重写历史隐藏失败。正式版本/tag发行不在默认同步授权内。
- 现有Git历史保留；删除前端以新增提交从当前分支移除，不擅自强推清除旧提交。

Release notes describe the final authorized change for a reader outside the conversation. Keep planned inference cases labeled planned. Follow [CHANGELOG](CHANGELOG.md), [CONTRIBUTING](CONTRIBUTING.md) and the persistent [AGENTS instructions](../AGENTS.md).
