# 开源发布与持续同步规范 / Publication and update synchronization

目标仓库：`git@github.com:copypasteltd/Hottest-animation-clones.git`；[GitHub项目](https://github.com/copypasteltd/Hottest-animation-clones)。主分支`main`。本篇记录用户明确要求的持续维护约定，不代表尚未完成的推送/远端CI已经通过。

The authorized target is the GitHub repository above. Use normal pushes to `main` for completed, reviewed work within the user's standing synchronization request. Do not force-push or overwrite unknown remote history. Report a failed push as failed synchronization.

## 1. 发布内容 / Public scope

- 原创源码、需求/契约、维护测试、纯虚构示例和静态文档演示。
- 根目录`README.md`为英文，`README.zh-CN.md`为中文，两者都包含方案、实际能力、命令、数据/版本关系、限制和维护路径。
- 详细文档仍在docs内；根README与AGENTS是用户本次新要求的入口例外，替代旧版“根目录不放README”约定。
- docs/assets只允许精确白名单文件：实际页面截图、录屏裁片、GIF和来源清单。不放真实视频、人像、第三方角色图或模型输出。
- 所有媒体都明确为作者自制几何示意页面的真实浏览器捕获，不表示姿态推理、视频迁移或真实数据效果。

Public scope is original source/specifications, synthetic examples and real captures of the synthetic documentation page. Neither MIT nor a repository push grants rights to redistribute private character images, music, source performances, model weights or upstream workflows.

## 2. 每次变更必须同步什么

| 变更 | 必须同步 |
|---|---|
| CLI/安装/依赖/目录 | 中英README、使用长文、配置、测试、更新说明 |
| Schema/动作字段/审核/版本规则 | 契约、样例、负例/业务测试、影响说明 |
| 页面/交互/可见文字 | 页面、双语文案、桌面/移动检查；需要时重录截图/录像/GIF，更新capture manifest |
| 实现进度/模型能力 | 两语言状态表、路线图，明确已测与未测，不能用漂亮图证明动作准确 |
| 角色/场景/媒体变更 | 本地版本/hash/批准记录；不自动入源码仓，不覆盖v1 |
| 发布/远端更新 | CHANGELOG、提交、正常push，核验远端commit；CI状态另查，不把排队叫通过 |

A change is not fully synchronized until the relevant English and Chinese docs, examples, tests, release notes and remote commit are consistent. A user instruction to hold a push or request review takes precedence. Unrelated local changes must be preserved.

## 3. 本地检查与提交

```bash
python -m pip install -e ".[dev]"
python scripts/check_project_docs.py
python scripts/check_release.py
python -m unittest discover -s tests -v
# 显式暂存本轮已经审阅的文件；不要强制添加真实媒体。
git add -- <reviewed-paths>
python scripts/check_repository.py
git diff --cached --check
git diff --cached --stat
git commit -m "docs: describe the specific change"
git push origin main
git ls-remote origin refs/heads/main
```

`check_repository`检查Git索引，是防误提交措施，不是完整安全审计；`check_release`检查公开README/页面/媒体清单，不能验证真实动作。公开克隆运行角色锁缺媒体应明确失败，不自动替换。首次安装依赖需要网络；之后维护检查不调用模型服务。

## 4. 页面捕获流程 / Capture workflow

1. `python scripts/serve_demo.py --port 8765`在loopback仅提供docs/demo内容。
2. 在实际浏览器打开，检查中文/英文、搜索/筛选、轨迹/来源、导出和移动布局。
3. 桌面PNG直接截图；开始真实页面录屏后执行Guided tour，等待最终界面稳定再停止。
4. 原始录制保存在本地忽略区；检查帧表，裁掉空白/等待，仅将有效操作片段转码成MP4和GIF。不得用程序画出假页面并称录屏。
5. 记录capture method、完整性、时间范围、变换、尺寸、hash、bytes、合成内容声明；查看转换后的媒体。
6. 更新README引用和清单。发布检查对精确媒体文件做hash/格式校验，严禁整目录放开任意二进制。
7. 停止本轮拥有的服务器、录制和浏览器会话，不停止用户其他服务。

Recording duration caps are reported honestly. The current short walkthrough is an excerpt of a complete, duration-limited browser capture, not a recording of the whole development task. Raw captures can remain local for auditing; the public manifest does not expose credentials or private device details.

## 5. 并发、远端差异与失败

- 推送前获取目标refs；空仓可以首次正常push。已有提交需先检查与本地关系。
- 远端更新与本地分歧时先fetch/比较，不用force覆盖。独立README初始历史需保留后再明确整合。
- SSH已授权的正常git传输不应打印私钥或token。缺权限/认证/网络时保留本地提交并报告具体错误，不换账号、伪造成功或静默改目标。
- push成功后比较本地HEAD和远端main；GitHub页面和CI另作验证。CI失败则修复后新增提交和推送，不重写已公开历史来隐藏失败。
- 发布证据、原始录像和含本地路径回执只留docs/validation或runs忽略区。

## 6. 更新说明最低内容

每轮说明包括：用户可见变化、原有行为与新行为、涉及的需求/数据版本、真实测试与结果、未测模型能力、页面媒体是否更新，以及提交与同步状态。未改界面的纯文档变更可以明确不重录，不无意义重复生成媒体。

Commit and release notes must describe the final change for a reader who did not see the conversation. Do not list only "update files" or claim an entire planned product is implemented. See [CHANGELOG](CHANGELOG.md), [CONTRIBUTING](CONTRIBUTING.md) and the persistent [AGENTS instructions](../AGENTS.md).
