# 实施计划与流程验证

用例对应 v0.6 的五项需求。验证点为下载交接、整片路线选择、定稿图绑定、工作流提交与结果取回。真实试跑按来源和各版本的任务回执登记。[产品需求](<../product/requirements.md>) · [当前覆盖](<../product/status.md>)

<a name="validation-order"></a>

## 实施顺序

1. 对三个站点分别核实下载技能的交接。首条闭环使用连续单镜、双手清楚的 Bilibili 单人站立手势视频。具体作品链接由用户后续提供。
2. 先走单人半身路线，将完整源片分别连到 SA02 F01 与 BM01 F05，核对工作流参数、回执和两个实际取回的结果。
3. 再接单人全身和双人半身／全身路线。各路线按整片输入、目标图、活动分支与取回记录登记。坐姿等预设按后续需要接入。[4090 接线](<../operations/h3-4090.md>)

<a name="acceptance-cases"></a>

## 计划用例

| 用例 | 需求 | 可核对的结果 |
| --- | --- | --- |
| TC-01 | R-01 | Bilibili、X、抖音各用一条获准链接。逐站核对选中的完整视频、下载方式及源片核验。Bilibili 样本覆盖分 P 选择。 |
| TC-02 | R-01, R-05 | 多个合理候选只询问一次目标。重复、访问受限、缺音轨等输入各有结果。符合复用条件的版本引用既有产物。 |
| TC-03 | R-02 | 用整条手势原片与整条脚步原片判半身与全身，分别记录选择理由和相关可见范围。 |
| TC-04 | R-02 | 判断共同表演、路人、换镜、人数变化、遮挡及不支持的姿态。无法匹配整片路线时登记原因并保留整条原片。 |
| TC-05 | R-02, R-03 | 半身匹配 F01／F05，全身匹配 F02／F06。双人两版均使用 SA02 与 BM01。客户指定时按指定绑定。否则随机一次，第二版互换，整片及重试沿用已记录的对应。 |
| TC-06 | R-03, R-04 | 核对指定目录的原工作流与实际执行图。适配时核对副本的身份。两次提交的运动输入都指向整条原片，工作流按跟随原片运镜的设置接线。 |
| TC-07 | R-04 | 4090 已有任务时仍向 ComfyUI 入队，核对两条原片的同版本成组顺序和独立回执。批次停止后停下所有未完成尝试，记录已确认取消或待核结果。批次执行中，明确失败且原因可修正时每版最多自动补跑一次。回执不明时核对原尝试。 |
| TC-08 | R-04, R-05 | 按回执找回并交付对应 MP4。结果缺失或未能取回时记录原因和该版状态，已取回的版本继续交付。 |
| TC-09 | R-05 | 每次生成尝试单独反馈。成功取回时给出 MP4 和最小交付说明，失败时说明原因和补跑安排。用户后续可点名原片或版本调整、重试。 |
| TC-10 | R-01, R-02, R-03, R-04, R-05 | 在会话提交一条作品链接，按每次生成结果收到两份各自取回的整片迁移 MP4。回执能分别追到同一原片、各自的定稿图及执行图。 |

<a name="delivery-review"></a>

## 交付条件

对应回执的 MP4 已实际取回并落盘，即可直接交付。只登记版本、输出路径、音轨处理及已知执行限制。跳过成品校验、逐帧比较、人工审查及用户确认。用户可以基于交付后的反馈单独调整或重试。[状态含义](<../operations/run-record.md>) · [填写模板](<../templates/动作迁移任务与交付模板.md>)
