# 实施计划与流程验证

用例对应 v0.7 的五项需求。验证点为下载交接、整片路线选择、定稿图绑定、工作流提交与结果取回。真实试跑按来源和各版本的任务回执登记。[产品需求](<../product/requirements.md>) · [当前覆盖](<../product/status.md>)

<a name="validation-order"></a>

## 实施顺序

1. 对三个站点分别核实下载技能的交接。首条闭环使用连续单镜、双手清楚的 Bilibili 单人站立手势视频。具体作品链接由用户后续提供。
2. 先走单人半身路线，将完整源片分别连到 SA02 F01 与 BM01 F05，核对工作流参数、回执和两个实际取回的结果。
3. 再接单人全身和双人半身／全身路线。各路线按整片输入、目标图、活动分支与取回记录登记。坐姿等预设按后续需要接入。[4090 接线](<../operations/h3-4090.md>)

<a name="acceptance-cases"></a>

## 计划用例

| 用例 | 需求 | 可核对的结果 |
| --- | --- | --- |
| TC-01 | R-01 | Bilibili、X、抖音各用一条获准链接。逐站核对选中的完整视频、下载方式及源片核验。Bilibili 样本覆盖分 P 选择。 |
| TC-02 | R-01, R-05 | 多个合理候选只询问一次目标。重复、访问受限、缺音轨等输入各有结果。同一版本有多个匹配结果时复用最近成功取回的一份，旧结果按尝试编号找回。 |
| TC-03 | R-02 | 用整条手势原片与整条脚步原片判半身与全身，分别记录选择理由和相关可见范围。 |
| TC-04 | R-02 | 判断共同表演、路人、换镜、人数变化、遮挡及姿态。遇到直接参与动作的道具时匹配目标图与工作流，缺配置时登记阻塞。无法匹配整片路线时保留整条原片并登记原因。 |
| TC-05 | R-02, R-03 | 半身匹配 F01／F05，全身匹配 F02／F06。双人两版均使用 SA02 与 BM01。客户指定时按指定绑定。否则随机一次，第二版互换，整片及重试沿用已记录的对应。 |
| TC-06 | R-03, R-04 | 核对指定目录的原工作流与实际执行图。适配时核对副本的身份。核对入队前有 SA02 和 BM01 两版计划，运动输入均绑定同一完整原片。两版就绪时同轮提交，工作流按跟随原片运镜的设置接线。 |
| TC-07 | R-04 | 核对含作品链接的消息是否获得新批次编号，并核对明确要求追加时的归属。两条一组时等待仍在下载的原片，组员失败或阻塞后允许单条入队。设备忙碌时照常提交，按回执核对成组顺序、停止范围和各尝试的实际状态。 |
| TC-08 | R-04, R-05 | 活跃批次按回执取回并交付。停止时反馈已生成但仍在远端的结果，恢复后按原回执取回。继续整批时，已取消任务另开尝试，已交付版本沿用成片。 |
| TC-09 | R-05 | 逐次反馈生成结果。会话恢复后用原回执补发未反馈的结果，用户已停止的批次等明确继续指令。工作流支持时，主动重做默认换种子，明确失败且可修正时最多自动补跑一次并优先沿用原种子。 |
| TC-10 | R-01, R-02, R-03, R-04, R-05 | 在会话提交一条作品链接，按每次生成结果收到两份各自取回的整片迁移 MP4。长期留存的批次记录能从两版成片追到同一原片、定稿图、各自的回执和实际执行图。 |

<a name="delivery-review"></a>

## 交付条件

批次运行中，按回执取回 MP4 并落盘后直接交付。停止期间已在远端生成的成片在批次恢复后取回。只登记版本、输出路径、音轨处理及已知执行限制。跳过成品校验、逐帧比较、人工审查及用户确认。用户可以基于交付后的反馈单独调整或重试。[状态含义](<../operations/run-record.md>) · [填写模板](<../templates/动作迁移任务与交付模板.md>)
