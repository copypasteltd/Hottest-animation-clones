# 实施计划与验收矩阵

下面的用例验证 v0.4 从作品链接到成片的五项需求。实际结果按样片、路线和工作流版本登记。[产品需求](<../product/requirements.md>) · [当前覆盖](<../product/status.md>)

<a name="validation-order"></a>

## 实施顺序

1. 按站点验证指定下载技能的交接，记录作品身份、下载方式、实际原片和媒体结果。首条闭环可使用任一完成下载核验的站点。
2. 选一条证据清楚且匹配项目目标图的路线，核对活动分支、真实输入和输出后执行首条完整样片。
3. 分别验证单人半身、单人全身、多人半身和多人全身。先核对对应目标图、审核状态与工作流输入，再按实际覆盖复用工作流。
4. 根据样片结果登记常规可用路线。增加坐姿等预设时，按其实际构图、角色和人数再验收。[4090 接线](<../operations/h3-4090.md>)

<a name="acceptance-cases"></a>

## 计划用例

| 用例 | 需求 | 验收证据 |
| --- | --- | --- |
| TC-01 | R-01 | Bilibili、X、抖音各用一条获准链接。每个站点完成下载和媒体核验后登记通过，Bilibili 样片核对多 P 选择。 |
| TC-02 | R-01 | 重复、受限和无法取得的链接均得到逐条结果。重复项可追到同一来源，其他失败项附具体原因。 |
| TC-03 | R-02 | 分别检查单人腰上手势和单人全身步法，以实际可见部位与关键时间点说明半身或全身选择。 |
| TC-04 | R-02 | 对共同表演者、偶然入镜路人、换镜或遮挡给出主体与区间记录。关键证据缺失时注明待复核的范围。 |
| TC-05 | R-02, R-03 | 在单人和多人两类下验证半身与全身目标图，核对姿态、S02、人物对应、版本和审核状态。缺图时可定位受影响的组合。 |
| TC-06 | R-03, R-04 | 核对实际工作流、活动分支、人物和场景输入。单图路线检查 S02 组合图，多人路线检查逐人映射。 |
| TC-07 | R-04 | 保存指定 4090 工作流的实际提交回执和对应结果。遇到回执不明时按原尝试核对队列、历史和实际输出。 |
| TC-08 | R-04, R-05 | 取回与提交对应的视频，确认非空、可解码、时长和媒体属性。缺失或损坏时登记结果和原因。 |
| TC-09 | R-05 | 对照源与成片的关键时刻，复核动作、节奏、目标人物、构图及 S02。所需脚步和多人关系都有对应证据。 |
| TC-10 | R-01, R-02, R-03, R-04, R-05 | 只提交一条作品链接，从已配置路线取回审核通过的 MP4。记录可按源 ID、目标图、工作流及提交回执定位。 |

<a name="delivery-review"></a>

## 成片判定

| 维度 | 审核依据 |
| --- | --- |
| 文件 | 对应原提交的文件非空且可解码。项目相对路径、分辨率、帧率、时长、流信息与 SHA256 可查。 |
| 人物 | 人物、画风和服装与目标图相符。多人逐个核对目标身份和表演者对应。 |
| 动作与节奏 | 对应区间的关键手势、脚步或互动保持顺序与节奏。以本次配置和原片时间为准，记录任何偏差及所属范围。 |
| 场景与取景 | 纯白背景与目标构图应出现的地面网格清楚。所需头、手、脚或站位在关键时刻可查。 |
| 音轨 | 实际原音、生成音、混合或静音与任务配置相符。含音频时核对与画面的同步情况。 |

样片审核记录应含执行区间、目标图和版本、工作流与回执、实际媒体及关键时刻的证据。所需维度有缺陷或证据不足时登记 `failed` 或 `needs_review` 和原因。媒体与审核均通过后才将该候选交付为成片。[状态含义](<../operations/run-record.md>) · [填写模板](<../templates/动作迁移任务与交付模板.md>)
